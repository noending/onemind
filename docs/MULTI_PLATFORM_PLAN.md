## 1. 当前技术判断

本项目由微信开发者工具生成，采用微信多端 MiniApp 架构。

它的主技术路线应保持为：

- 原生微信小程序语法：`WXML / WXSS / JS / JSON`
- 微信开发者工具多端工程：`projectArchitecture: multiPlatform`
- MiniApp 多端配置：`mini-ios`、`mini-android`、`mini-ohos`

因此后续不应改成 `uni-app` 或 `Taro`，除非决定完全迁移技术栈。

## 2. 已有配置说明

- `project.config.json`: 微信开发者工具配置，负责小程序编译和多端工程识别。
- `project.miniapp.json`: iOS、Android、OHOS MiniApp 的 SDK、资源、隐私与扩展能力配置。
- `app.miniapp.json`: 将微信小程序适配到 MiniApp 容器的配置。
- `i18n/base.json`: 多端应用名称。
- `miniapp/ios/i18nInfo.json`、`miniapp/android/i18nInfo.json`: 端侧名称信息。

## 3. 产品 MVP 范围

首期只做一个核心闭环：

`选内容 -> 生成记忆计划 -> 分段训练 -> 到期复习 -> 继续下一段`

首期页面：

- 今日：推荐内容、今日待复习任务。
- 内容库：短咒、短偈、经文片段。
- 训练：分段熟悉，后续扩展提示、遮挡、填空、跟读。
- 计划：复习节点和掌握度。
- 我的：平台识别、提醒策略、后续能力说明。

## 4. 多端策略

### 微信小程序

- 作为首发验证渠道。
- 优先实现内容选择、记忆计划、本地存储、订阅消息提醒。

### iOS / Android MiniApp

- 使用当前 `mini-ios`、`mini-android` 配置输出端侧容器。
- 后续重点验证通知、音频播放、缓存和隐私描述。

### HarmonyOS / OHOS MiniApp

- 使用 `mini-ohos` 配置作为鸿蒙端入口。
- 后续重点验证通知能力、文件权限、音频能力和 UI 兼容性。

## 5. 工程阶段

### Phase 1: 原生小程序 MVP

- 补齐应用入口和 5 个页面。
- 建立内容数据、记忆曲线和本地存储。
- 在微信开发者工具中跑通微信小程序模拟器。

### Phase 2: 多端容器验证

- 使用微信开发者工具多端能力验证 iOS、Android、OHOS 配置。
- 补齐图标、启动图、隐私说明。
- 建立不同端的提醒策略和端能力降级逻辑。

### Phase 3: 内容与提醒增强

- 接入真实内容后台。
- 接入微信订阅消息。
- 接入 App / OHOS 系统通知适配。
- 增加音频跟读能力。

### Phase 4: 数字法藏与权限

- 引入组织、角色、权限。
- 支持公开、封闭、指定人员可见。
- 支持数字资产版本、维护人、审计日志和交接机制。

## 6. 成功指标

- 首次计划创建率。
- 3 日复习完成率。
- 单段内容背会率。
- 第二段内容开启率。
- 节日推荐加入计划率。
- 组织版资料上传、授权、交接成功率。
