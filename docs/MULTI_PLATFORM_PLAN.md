# 一念法藏多端实施计划（统一基线）

更新时间：2026-05-28

## 0. 当前总目标

在微信开发者工具多端 MiniApp 架构下，完成 oneMind 前台 MVP 可演示版本，并持续推进 Phase 3/4 的后端与管理后台能力。

当前执行口径：

- 前台：`PRODUCT_REQUIREMENTS.md` + 本计划
- 后台：`ADMIN_BACKEND_REQUIREMENTS.md`
- 数据：`DATABASE_DESIGN.md` + `backend/schema.sql`
- 接口：`API_CONTRACT.md`

## 1. 技术路线（不变）

- 原生小程序语法：`WXML / WXSS / JS / JSON`
- 多端工程：微信开发者工具 `multiPlatform`
- 目标端：微信小程序、iOS MiniApp、Android MiniApp、OHOS MiniApp

不做迁移：

- 当前阶段不迁移到 uni-app/Taro，避免重构成本与节奏风险。

## 2. 前台信息架构（锁定）

说明：

## 6. 风险与应对

风险：

- 多端资源规范不一致导致部分端视觉偏差。
- 登录与通知真实链路受平台配置影响较大。
- 文档与实现偏离会导致反复返工。

应对：

- 每完成阶段必回写本计划状态。
- 所有新增字段先更新 `schema.sql` 与 `API_CONTRACT.md`，再改前台。
- 每次发版前执行一轮“微信模拟器基准复测”。

## 7. 状态回写规则（强制）

每完成一个阶段或子阶段，必须同步更新：

避免出现“代码已改但文档旧口径”的情况。
